# Scanner ESP Gateway: QA review and development backlog

Reviewed September 19, 2026, against commit `674ea0b` plus the existing, uncommitted five-minute display/LED timeout changes. ESP-IDF 5.5.5; esp_tinyusb 2.3.0; TinyUSB 0.21.0~2; ESP32-S3; 300 dpi RGB, JPEG quality 75.

## Assessment

**The firmware builds and its existing host tests pass, but storage and image-preservation defects prevent a reliability sign-off.** The highest priorities are completing accepted USB writes safely, reporting physical SD write failures to Windows, and preventing automatic crop from deleting real page content.

The earlier hardware session found an empty FAT32 root directory, approximately 63 MB of recoverable chains, and a USB disconnect. This review reproduced plausible storage failure mechanisms in host simulations; it did **not** establish the cause of that particular incident. The visual sleep branch only changes the display and LED. Its temporal proximity to the incident is not proof of causation.

This QA pass reviewed application code, the storage dependency paths it uses, tests, build/configuration, and Windows utility scripts. It added this report and diagnostic reproductions. Firmware behavior was not changed or flashed, and the SD card was not written, repaired, or scanned during this pass.

## Prioritized findings

P1 means fix before relying on the device for important scans or writable USB storage. P2 means a meaningful correctness or recovery defect. P3 means a lower-priority robustness or usability defect. “Reproduced” below means a host reproduction unless stated otherwise. Source line numbers refer to the reviewed workspace.

### QA-01 — P1: USB detach can discard an accepted write

**Reproduced.** `main/usb_storage.c:160–171` parks the TinyUSB task in a deferred disconnect callback. The dependency separately defers the physical SD write (`managed_components/espressif__esp_tinyusb/tinyusb_msc.c:347–383`). A valid event order is:

```text
queued WRITE10 transfer completion
queued disconnect callback
  -> processing the transfer completion queues its SD write behind disconnect
  -> disconnect parks the task
  -> teardown destroys the queue containing the SD write
  -> the ESP is granted filesystem ownership
```

The write-protection flag cannot cancel a receive already submitted to USB; its completion calls the write callback without another writable check (`msc_device.c:895–924`). The reproduction returned `acquire=ESP_OK`, `app_owned=1`, `accepted_bytes=512`, `SD_writes=0`, and one outstanding dependency write after the queue was deleted.

**Required change:** account for accepted, queued, and executing I/O before granting APP ownership. Stop accepting new operations, finish or fail outstanding work, and only then tear down USB. Simply allowing the event loop to run again could reintroduce the previous read/mutex race.

**Acceptance:** test completion-before-detach, write-behind-detach, multiple sectors, host reset, timeout, and recovery. No accepted write may disappear silently.

### QA-02 — P1: Physical SD write failures are not reported to Windows

**Reproduced.** `tinyusb_msc.c:1276–1289` reports all bytes accepted before the SD write occurs. The later write function only logs a medium failure (`tinyusb_msc.c:306–327`). Injecting `ESP_FAIL` still produced a 512-byte accepted result, with no error propagated to the command or application.

**Required change:** report successful completion only after successful physical I/O, using a compatible synchronous path or TinyUSB's asynchronous completion mechanism. Preserve a tested dependency patch or explicitly verified dependency version; do not depend on an untracked edit to `managed_components`.

**Acceptance:** injected SD write failure/timeout must produce failed USB command status and an application-visible storage error.

### QA-03 — P1: Automatic scans forcibly remove writable host storage

**Confirmed architecture risk; actual corruption depends on timing.** The device exposes writable storage (`usb_storage.c:293`) and takes it away when paper is detected (`main.c:88`). Draining device-side writes cannot flush filesystem work still cached on Windows or complete a multi-command FAT update. The 250 ms delay starts after disconnect and is not a host-release handshake. Windows documents delayed writes in its [file caching guidance](https://learn.microsoft.com/en-us/windows/win32/fileio/file-caching).

**Recommended design:** normal automatic-scan mode exposes read-only USB storage; a separate writable maintenance mode permits host additions/deletions and suspends automatic acquisition until the host safely releases the volume. If always-writable access remains a requirement, define and verify explicit host release. A quiet interval alone is insufficient.

This is a proposed behavior change, not a change made by this review. It preserves the requested ability to read and write the SD card through a controlled mode.

### QA-04 — P1: Width cropping can permanently remove legitimate content

**Reproduced.** `jpeg_width_crop.c:297–312` samples roughly 24 rows and uses dark block averages to infer a right paper edge. `scanner_capture.c:127` removes the original after publishing the crop.

A valid full-width 2550 × 384 fixture containing legitimate dark content on the right and a white item at x=2000–2399, y=8–15 was reduced to **1552 × 384**. The white item was removed. The result remains a decodable JPEG; image-format validation cannot detect this loss.

**Required change:** offer crop off/original preservation, and avoid discarding the only original based on this heuristic. Improve edge confidence against a corpus containing dark photos, borders, skew, receipts, and mixed widths. More sampling helps but darkness alone cannot prove absence of paper.

### QA-05 — P2: Invalid unsampled JPEG rows can be published

**Reproduced.** Height validation checks restart-marker structure (`jpeg_crop.c:76–87`); width processing decodes sampled rows and returns early when no crop is needed (`jpeg_width_crop.c:299–310`). Removing every entropy byte between the first two restart markers passes both stages. A decoder reconstructed a visibly damaged band at y=8–15.

**Required change:** validate every retained row's expected MCU count and bitstream structure, including the no-crop path. A tolerant decoder's successful `load()` is not sufficient integrity evidence.

### QA-06 — P2: Existing `.CRP` files can be overwritten or deleted

**Reproduced.** Scan allocation checks `.JPG` and exclusively creates `.TMP`, but does not reserve `.CRP` (`scanner_capture.c:69–76`). Width crop opens its target with `"wb"` and removes it on any outcome other than successful cropping (`jpeg_width_crop.c:320,338`). A valid page needing no crop deleted a pre-existing target containing sentinel data.

**Required change:** reserve all working names exclusively; only remove files created by the current attempt. Cover host-created and orphaned working-file collisions.

### QA-07 — P2: The screen hides failed or incomplete scan outcomes

**Reproduced in the real main-loop code with stubs.** A post-feed crop error becomes `READY TO SCAN` at the next empty-feeder poll, about five seconds later, while the last filename still refers to a previous success or `NONE` (`main.c:63–66,104–112`). A complete image with `released=false` also receives unconditional completion status (`main.c:118–122`), hiding the protocol's cleanup warning. A truncated final FIN response reproduced that warning; persistence of the scanner lock is not established.

**Required change:** retain last outcome separately from current readiness. Distinguish “file saved” from “scanner cleanup failed,” and retain failed filename/stage/error until acknowledged or superseded by a later result.

### QA-08 — P2: Storage failures can leave no usable recovery path

**Partly reproduced; startup behavior confirmed by inspection.** Failed handoff plus failed recovery returns from `app_main`, ending scanner polling, UI processing, and the idle timer (`main.c:92–95,113–117`). At boot, an unmountable FAT volume causes `ESP_ERROR_CHECK(usb_storage_start_app())` before USB exposure (`main.c:47`).

Refusing unsafe filesystem access is appropriate. Improve this into an explicit stopped/recovery state, with a persistent fault code and reset/recovery instruction. Consider read-only raw USB recovery exposure after mount failure. Never automatically format a damaged card or force repeated writes when ownership is uncertain.

### QA-09 — P2: File timestamps can silently become invalid again

**Confirmed by inspection.** Time synchronization is a single boot attempt (`scanner_wifi.c:65–94,191`). If home Wi-Fi, DNS, or NTP is unavailable, scanning continues without a valid date, and the current UI has no clock-valid indicator.

**Required change:** expose time validity, support a bounded retry/manual setting, and distinguish unknown time from a synchronized clock. Avoid switching Wi-Fi during an active scan. Timezone is currently fixed to Eastern time.

### QA-10 — P2: The image QA tool falsely verifies JPEG quality

**Reproduced.** For qualities other than 50 or 100, `tests/verify_scan.py:33–40` only checks that some quantization value exceeds one. A generated quality-50 image invoked with `--quality 75` exited successfully and printed `quality 75 tables`.

**Required change:** compare against verified Epson quantization tables for supported settings, or report quality as unverified. Include wrong-quality negative fixtures. Use explicit validation failures instead of assertions if the verifier must also work under Python optimization (`-O`).

### QA-11 — P2: Host crop tests fail in a clean checkout

**Reproduced.** `tests/test_jpeg_width_crop.py:12–18` links into `build/jpeg_width_crop_test.dll` without creating its parent. Running it with only its tracked source inputs and no existing build directory fails before the test cases execute.

**Required change:** compile into a temporary directory, as the other tests do. Add a clean-checkout CI job and document/pin Python test dependencies.

## Optimizations to evaluate after correctness fixes

These are candidates for measurement, not claimed speed gains. Use the same document, resolution, quality, card, and power conditions for comparisons, and compare both image content and file integrity.

| Order | Optimization | Why it may help | Measurement / constraint |
|---|---|---|---|
| 1 | Measure capture phases separately | Current duration combines reception, storage, crop, and publication; it does not isolate the bottleneck. | Record connect, receive/write, height validation, width analysis/rewrite, and USB remount separately. Include min heap, largest free allocation, stack headroom, and error counters. |
| 2 | Benchmark MSC buffers of 4, 8, and 16 KiB after write correctness is fixed | Current `CONFIG_TINYUSB_MSC_BUFSIZE` is 512 bytes, creating many small operations. | Measure sequential reads/writes, memory use, and disconnect behavior. Preserve sector alignment and in-flight I/O guarantees. |
| 3 | Combine JPEG validation and row indexing | Height validation and width indexing each read the JPEG; cropping adds another read/write pass. | Reduce redundant SD reads while validating every retained row. Track worst-case latency and RAM. |
| 4 | Size crop allocations to actual data | Width processing reserves a 64 KiB header buffer plus row indexes and its largest compressed row. | Bound headers and entropy rows; monitor allocation failures and fragmentation. Enable PSRAM only after verifying board hardware and DMA/internal-memory requirements. |
| 5 | Replace per-byte bookkeeping with per-chunk updates | `esci_scan.c:122` inspects every image byte only to maintain the byte count and first/last bytes. | Preserve fragmented-input, one-byte-chunk, overflow, and JPEG-boundary behavior; benchmark CPU savings. |
| 6 | Avoid scanning names from 0001 for every page | The current loop performs repeated filesystem lookups and caps names at 9999. | Cache/reconcile the next number or index the directory once; remain collision-safe after Windows adds/deletes files. |
| 7 | Render only changed UI regions | A full 320 × 172 RGB565 redraw sends 110,080 bytes, approximately 22 ms of wire time at 40 MHz before overhead. | Measure redraw CPU/time during scanning; keep DMA buffer ownership explicit. Benefit may be modest because progress redraws are already limited. |
| 8 | Adaptive idle polling and Wi-Fi power settings | Visual sleep leaves two-second scanner polling and `WIFI_PS_NONE` active. | Measure current draw, page-detection delay, Wi-Fi stability, and USB operation. Preserve immediate response after activity. |
| 9 | Allocate flash space for planned features | The 16 MB flash device currently uses only a 1 MiB application slot, with 90,016 bytes left. | Design and test a custom partition layout before substantial UI/PDF/OTA expansion; preserve NVS and any existing flash data. |

ESP32-S3's native USB interface uses **12 Mbit/s full speed**. That is a bus rate; real file throughput is lower. Buffer tuning cannot turn it into a 480 Mbit/s link. See Espressif's [USB transfer-rate documentation](https://docs.espressif.com/projects/esp-iot-solution/en/latest/usb/usb_overview/usb_otg.html).

## Potential features

All proposed core features run on the ESP. They preserve the simulated USB-drive approach and do not require a companion PC application.

| Priority | Feature | User benefit | Scope / dependency |
|---|---|---|---|
| First | Scan mode and writable SD maintenance mode | Automatic scanning plus intentional host file management with safer ownership transitions. | Requires QA-01/02 fixes and a verified safe-release workflow. |
| First | Persistent last result and diagnostics screen | Explains where a scan failed and whether the device is ready, finalizing, or stopped. | Small/medium. Retain concise state in RAM/RTC or bounded fault records; no need to recreate `GATEWAY.TXT`. |
| First | Crop off / preserve original / conservative auto crop | Protects dark documents and makes bad crop decisions recoverable. | Small/medium; define storage cost and never silently remove the only source. |
| Next | Settings menu with saved profiles | Switch between verified 300/600 dpi, quality, crop policy, and sleep timeout without reflashing. | Medium. Persist in NVS and drive request, validators, and display from one validated configuration. |
| Next | Free-space and card-error display | Gives a useful warning before an avoidable storage failure. | Small/medium. Query only while APP owns the filesystem; estimate conservatively and still handle write errors. |
| Next | Physical wake and menu control | Wake the screen and inspect settings without feeding a page. | Small/medium. Respect BOOT pin strapping; debounce and distinguish short/long presses. Cancel must use a verified scanner protocol path. |
| Next | Clock status, timezone, and resync control | Prevents unexplained 1980-era dates and supports travel/network outages. | Medium. A battery-backed RTC is an optional hardware extension if correct cold-boot time must work offline. |
| Next | Batch mode with JPEG pages in a PDF | Produces one document from several scans. | Medium/large. JPEG streams can be embedded without another image encode; define finish/cancel, page recovery, and size limits. |
| Later | Filename prefixes, document counters, and folders | Makes stored documents easier to identify. | Medium. Current FAT configuration disables long filenames; design naming and collision handling accordingly. |
| Later | Receipt handling and crop margins | Removes unused area from very narrow documents and allows an edge safety margin. | Medium. Current half-canvas guard leaves a 600-pixel receipt at the full 2550-pixel width. Requires content-preservation tests. |
| Later | Orientation controls or a small preview | Makes upside-down pages and crop choices easier to notice. | Medium/large. Verify scanner-supported orientation first; ESP-side JPEG transformations and previews need RAM/latency analysis. |
| Later | Firmware update with rollback | Reduces repeated BOOT/RESET flashing steps. | Large. Requires new partition layout, verified update transport, rollback, and credential protection. |

OCR/searchable PDF and complex image enhancement are lower-priority research items for this ESP32-S3 build, which has no PSRAM enabled and limited runtime headroom. Simple JPEG-in-PDF is the more practical first document-format feature.

Diagnostics deserve early attention: the current console selects USB Serial/JTAG while the application uses USB OTG MSC. Those controllers share the internal PHY, so a UART debug path is useful for observing USB teardown faults continuously. A composite CDC/MSC interface is another option, but logs on that interface would also disappear during the current whole-driver teardown. See Espressif's [PHY-sharing explanation](https://docs.espressif.com/projects/esp-usb/en/latest/esp32s3/usb_host.html#external-phy-configuration) and [device-stack composite support](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/api-reference/peripherals/usb_device.html).

## Test work required for a reliability sign-off

1. **Storage correctness:** extend lifecycle tests to include the real deferred-write contract, SD failure reporting, concurrent host transfer completions, mount/unmount/USB install failures, and all recovery states. Preserve the existing no-format and exclusive-ownership safeguards.
2. **Capture orchestration:** test filename collisions across JPG/TMP/CRP, file-open/connect failure, short writes, flush/fsync/close failure, crop failure, rename failure, and deletion of originals. Current tests primarily exercise components in isolation.
3. **Image preservation:** test 300/600 dpi and 50/75 quality with white and dark pages, photos, right-edge text, skew, receipts, thin borders, damaged entropy, and truncated data. Compare retained pixels against originals, not just successful decoding.
4. **Recovery/UI/time:** test failed capture followed by empty feeder, cleanup failure, failed USB recovery, missing/bad SD card at boot, failed LCD/LED transitions, unavailable NTP, and scanner reconnects. Keep errors visible and ownership safe.
5. **Hardware acceptance on expendable media:** after storage fixes, verify host write/read hashes, repeated scan handoffs, deliberate host-I/O overlap, power interruption at controlled phases, full-card handling, long idle/wake, and extended batches. Recheck FAT after each fault scenario. Do not use the unresolved recovery card for destructive testing.
6. **Repeatable CI:** make host tests independent of existing build artifacts, pin required tools/dependencies, build from a clean checkout with dummy test credentials, and archive test results without private firmware images or real scanned documents.

## Diagnostic reproductions included

```powershell
python tests/qa/reproduce_storage_write_handoff.py
python tests/qa/reproduce_crop_findings.py
```

These programs require the existing Python `ziglang`/Pillow test environment. The storage reproduction also requires the managed dependencies restored by an ESP-IDF build. Both compile the actual reviewed source and perform **no device I/O**.

**Exit zero means the documented defects were reproduced, not that the firmware is correct.** They are intentionally separate from the passing regression suite. After fixing a defect, convert its reproduction into a test asserting correct behavior. The crop script keeps synthetic fixtures in a new TEMP directory for inspection; the storage script removes its temporary compilation files.

Recommended implementation order: **storage write completion and host ownership → preserve scan originals and validate every row → fault visibility and recovery → benchmarked speed/memory improvements → settings and document features.**
