# Scanner controls and document features implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add practical ESP-native controls, document output, and maintainability features on the verified reliability baseline.

**Architecture:** A validated immutable job configuration feeds protocol, capture, validators, and display. Main remains the only scanner/filesystem/UI owner; input tasks enqueue events. Optional outputs and updates use the same safe ownership/publication boundaries.

**Tech Stack:** Existing ESP-IDF/C firmware, NVS, FatFs, streaming JPEG processing, small custom display/menu models, IDF application-update APIs.

**Spec:** [Design brief](../specs/2026-09-19-qa-improvements-design.md). Prerequisites: [R10](2026-09-19-reliability.md) and the [accepted performance baseline](2026-09-19-performance.md); P2 is required before large features/update work.

## Global constraints

- Target the existing Waveshare ESP32-S3-LCD-1.47 and Epson ES-60W; verify the physical board revision before enabling new pins or PSRAM.
- Use ESP-IDF 5.5.5 and TinyUSB 0.21.0~2; maintain a checked-in, narrowly patched esp_tinyusb 2.3.0 override.
- Default scanning remains 300 dpi RGB, JPEG quality 75, with a 300-second display/LED timeout.
- Only one owner may access the SD filesystem; never format automatically or overwrite an existing scan or working file.
- Keep credentials and private firmware binaries out of Git, CI artifacts, logs, and published reports.
- Do not recreate GATEWAY.TXT or require a companion PC application.
- Use expendable media for write-fault and power-loss testing; the previously damaged card is excluded.

## Review focus

- Changing menu settings mid-page must not change that page's request/validation: F1/F2.
- A wake gesture must not also select a destructive or state-changing action: F2.
- Time resync or free-space inspection must not violate storage/scanner ownership: F3.
- Batch/PDF interruption must leave every published original readable: F5.
- A failed or unverified firmware update must not replace the active application: F8.

## F1 — Validated settings and saved profiles

**Files:** extend `scanner_settings.h`; create `scanner_settings.c`, `scanner_settings_nvs.c/.h`, `tests/test_scanner_settings.c`, `tests/test_scanner_settings_nvs.c`; modify ESC/I, capture, display interfaces and parameter tests.

**Interfaces:** define the following once in `scanner_settings.h` and use the same types in every task:

```c
typedef enum { SCANNER_ORIGINAL_ONLY, SCANNER_AUTO_WITH_ORIGINAL }
    scanner_crop_policy_t;
typedef enum { SCANNER_TZ_EASTERN, SCANNER_TZ_UTC } scanner_timezone_t;
typedef struct {
    uint16_t dpi;                  /* 300 or 600 */
    uint8_t jpeg_quality;          /* 50 or 75 */
    scanner_crop_policy_t crop;
    uint16_t visual_idle_seconds;  /* 0, 60, 300, 900; 0 disables timeout */
    scanner_timezone_t timezone;
} scanner_settings_t;
void scanner_settings_defaults(scanner_settings_t *out);
bool scanner_settings_validate(const scanner_settings_t *settings);
uint16_t scanner_settings_canvas_width(const scanner_settings_t *settings);
uint16_t scanner_settings_canvas_height(const scanner_settings_t *settings);
```

Declare persistence separately in `scanner_settings_nvs.h`, which includes the settings and ESP error types:

```c
esp_err_t scanner_settings_load(scanner_settings_t *out, bool *used_defaults);
esp_err_t scanner_settings_save(const scanner_settings_t *settings);
```

Update the scan declaration in `esci_scan.h`, which includes `scanner_settings.h`; settings must not depend on the protocol header:

```c
esci_result_t esci_scan(const esci_io_t *io, const scanner_settings_t *settings);
```

F1 updates `scanner_capture.h` to the following usable interface; F2 deliberately extends it with cooperative servicing:

```c
scanner_capture_result_t scanner_capture(
    uint32_t gateway_ip, const scanner_settings_t *settings,
    scanner_progress_fn progress, void *progress_context);
```

- [ ] Add all four DPI/quality combinations, invalid values/enums, immutable snapshot, corrupt/truncated schema, and interrupted NVS write tests. Run the full host runner red.
- [ ] Replace compile-time request/bounds/footer constants with an explicitly copied, validated settings snapshot. At 300 dpi use 2550 x 4200; at 600 use 5100 x 8400. Original-only still validates and normalizes height; auto mode may add a derivative while retaining the original.
- [ ] Defaults are 300/75, `SCANNER_AUTO_WITH_ORIGINAL`, 300 seconds, Eastern. Add three selectable initial profiles: Everyday 300/75, Smaller files 300/50, Detail 600/75. Permit 600/50 through editing. Unsupported resolutions/qualities are rejected rather than silently clamped.
- [ ] Initialize NVS once at application startup. Serialize a version/length/generation/checksum plus fields explicitly, using two records and selecting the newest valid one. Do not persist native padded structs, erase NVS on error, or save on each button press. Save only on explicit idle Save; failed persistence retains the previous active settings. Future schema additions must preserve older valid profiles or use an explicit migration.
- [ ] Make active `settings.timezone` the sole timezone authority. Apply it after loading the validated settings at boot and after a successful idle Save; remove the Wi-Fi module's hardcoded Eastern override. Failed Save changes neither active timezone nor settings. Test reboot consistency, failed Save, and deferred application during capture; F3's manual clock action consumes this committed timezone.
- [ ] Run protocol/capture/display/NVS tests and physically scan all four combinations. Verify actual JPEG dimensions, registered quantization tables, and footer. Commit `feat: add validated persistent scan profiles`.

## F2 — Physical menu, wake, and cooperative control servicing

**Files:** extend R3 button modules; create `scanner_menu_model.c/.h`, `gateway_control.c/.h`, `tests/test_scanner_menu_model.c`, `tests/test_gateway_control.c`; modify main scheduling, scanner I/O waits, JPEG service boundaries, display formatting.

**Interfaces:** define `scanner_service_fn` and pass it from main through capture and processing. Main invokes the callback; it is not a second scanner worker.

```c
typedef void (*scanner_service_fn)(void *context);
typedef enum { BUTTON_DOWN, BUTTON_SHORT, BUTTON_LONG } button_event_kind_t;
typedef struct { button_event_kind_t kind; int64_t at_us; }
    scanner_button_event_t;
bool scanner_button_next(scanner_button_event_t *event);
void gateway_control_service(void *context);
scanner_capture_result_t scanner_capture(
    uint32_t gateway_ip, const scanner_settings_t *settings,
    scanner_progress_fn progress, void *progress_context,
    scanner_service_fn service, void *service_context);
```

- [ ] Test startup-held BOOT, 30 ms debounce, queue overflow, wake-only first gesture, long-press suppression of short release, menu timeout, and deferred actions. R3's minimal hold shortcut is intentionally replaced by the menu at this release.
- [ ] Use an input-only GPIO0 sampler every 10 ms with an eight-event queue. Choose an 800 ms long press. Awake short press cycles status/last result/diagnostics; long opens menu. Menu short advances, long selects. Include explicit Save and Back; after 30 seconds without input discard unsaved edits. The first press while asleep wakes only and consumes the rest of that gesture.
- [ ] Opening the menu suspends automatic page triggering. Closing requires a fresh feeder debounce. Changes to settings, time, or storage mode wait for a healthy idle owner; acknowledgement never clears a storage fault. In writable mode show host-eject state and block forced resume. During capture allow wake/diagnostics and a `STOP AFTER PAGE` request; do not send an unverified immediate cancellation command.
- [ ] Replace long main sleeps with <=100 ms scheduling ticks. Make network waits use <=100 ms select slices while retaining absolute/inactivity limits and partial-transfer semantics. Service bounded UI events between waits/JPEG rows/phase boundaries. The callback cannot recursively capture, mount FAT, switch Wi-Fi, or save NVS. Measure separately the delay imposed by synchronous SD operations; do not claim universal 100 ms response.
- [ ] Test event delivery during a stalled socket, derivative processing, full queue, handoff, and STOPPED state. Physically verify no accidental maintenance/update action when waking, menu matches active profile, and the five-minute timeout still behaves correctly. Commit `feat: add button menu and bounded UI servicing`.

## F3 — Card status and controlled clock actions

**Files:** create `scanner_storage_info.c/.h`, `tests/test_scanner_storage_info.c`; extend clock model, Wi-Fi service, menu, diagnostics; add `tests/test_scanner_wifi_service.c` and clock-event cases.

**Interfaces:** `scanner_storage_info_t` holds capacity/free bytes, validity, sample generation, and last error. Refresh only with confirmed APP ownership; cached information is labeled stale after writable maintenance. Extend the R7 clock interface:

```c
esp_err_t scanner_clock_set_manual(int64_t unix_seconds);
bool scanner_wifi_request_time_sync(void);
void scanner_wifi_service(int64_t now_us);
```

- [ ] Add tests that a USB-owned/unreleased card rejects free-space refresh, an allocation failure does not block original publication, and stale card information never appears as current. Cache at boot/APP ownership and after capture. Estimate space conservatively for original plus derivative; still handle actual disk-full errors.
- [ ] Show card free space, last card error, and clock source/validity in diagnostics. If only derivative space runs out, show `ORIGINAL SAVED; CROP FAILED` and preserve the page.
- [ ] Implement explicit Resync and manual date/time actions. Route timezone changes through F1's settings Save; convert local date/time using that committed timezone before calling the manual setter. Validate leap years/month lengths and reject nonexistent or ambiguous daylight-saving local times with an explicit correction prompt; label accepted manual time MANUAL. Cold-boot historical NVS time is not current time. A battery-backed RTC is an optional hardware project, not a hidden prerequisite of this software task.
- [ ] Refactor home-association/SNTP/scanner-return into bounded states with queued Wi-Fi events. Defer requests during a job, loaded-page acquisition, unreleased writable mode, or uncertain storage. Pause triggering during sync and resume only after scanner reconnection plus fresh debounce. Use one bounded attempt per explicit request; keep a previous valid clock if resync fails.
- [ ] Test home AP/DNS/NTP loss, late events from the previous network, scanner reconnect failure, deferred requests, missing credentials, invalid manual time, and timezone change outside capture. Verify new file timestamps on expendable media. Commit `feat: expose card health and controlled time settings`.

## F4 — Naming, folders, and document counters

**Files:** extend `scan_files.c/.h`, settings schema/menu, capture results; create `tests/test_scan_naming.c`; update display and batch path consumers.

**Contract:** use an uppercase 1-4 character ASCII alphanumeric original prefix plus four digits, default `SCAN0001.JPG`; keep reserved derivative `CROP0001.JPG`. Reject reserved prefixes such as `CROP`, `DOCS`, and update/control names. Optional date folders use `YYYYMMDD`; invalid time uses `UNDATED`. Keep 8.3 names and bound relative paths to 96 bytes. Retain basename fields for display and add explicit relative-path fields for downstream consumers.

Use one shared scan counter across all original prefixes within each folder; a suffix occupied by any recognized original/working/derivative name is unavailable. Changing prefix cannot restart numbering onto another page's `CROPnnnn.JPG`. Capture returns the exact associated derivative path; batch/preview code must never infer association from digits alone.

- [ ] Test prefix/path traversal rejection, reserved names, length limits, unknown date, counter exhaustion, prefix changes with shared derivative numbering, host-created collisions, and maintenance invalidation of P6 hints. Run capture/naming tests red.
- [ ] Extend reservation checks across original/derivative/legacy working names in the selected folder. Create folders only with APP ownership; treat permission/I/O errors as errors. Never reuse an existing final filename even if its size is zero.
- [ ] Persist profile preferences through the versioned F1 schema; reconcile directory contents on ownership acquisition. Store the actual folder/profile snapshot with each job so an idle setting change cannot move a completed page unexpectedly.
- [ ] Verify Explorer-visible names, collisions, reboot persistence, date rollover, and a full 9999-name namespace in synthetic tests. Commit `feat: add bounded scan naming and date folders`.

## F5 — Recoverable multipage JPEG-in-PDF batches

**Files:** create `scanner_batch.c/.h`, `pdf_writer.c/.h`, `tests/test_pdf_writer.py`, `tests/test_scanner_batch.c`; extend menu, scan result, ownership orchestration, and file allocator.

**Contract:** Begin Batch, Add Page through ordinary scanning, Finish Batch, and Cancel Batch. Cancel stops grouping and keeps all published JPEGs. Default PDF pages use the original, with a deliberate per-batch choice to use available cropped derivatives. Limits: 100 pages or 1 GiB output, whichever is reached first. Use `DOCSnnnn.PDF` with exclusive `DOCSnnnn.TMP`; published pages remain ordinary JPEGs.

```c
typedef struct {
    char relative_path[96];
    uint16_t width, height, dpi, rotation_degrees;
    uint32_t bytes;
    uint8_t sha256[32];
} pdf_page_t;
/* Paths are validated APP-owned files; output is an exclusively opened TMP. */
bool pdf_write_jpeg_pages(FILE *output, const pdf_page_t *pages, size_t count,
                          scanner_service_fn service, void *context);
```

- [ ] Generate public synthetic JPEG fixtures and test page count, order, MediaBox dimensions (`pixels * 72 / dpi`), DCTDecode streams, stream lengths, xref offsets, trailer, corrupt/missing inputs, and bounds. Verify embedded JPEG stream hashes equal the chosen source streams. Use a PDF parser and render the synthetic results in the host test environment; add required packages to test requirements.
- [ ] Assemble the PDF by streaming JPEG bytes in bounded chunks without image re-encoding. Track bounded object/xref metadata in RAM, never a whole document image. Finish structure, flush/sync/close, validate, then publish without replacement. A failure retains original pages and an incomplete PDF TMP, not a false completed PDF.
- [ ] Reserve `DOCSnnnn.JRN`, `DOCSnnnn.TMP`, and `DOCSnnnn.PDF` together; exclusively create the owned journal. Record begin, page, finish-intent, completed, and abandoned states in an append-only versioned format with sequence and record checksum. Page records include bounded exact original/selected-source paths, dimensions/size, rotation, and SHA-256 of the selected source. Sync before acknowledging membership. Cancel records abandoned state and retains every original; the journal exists only for explicit batch mode.
- [ ] On resume/assembly, accept only complete valid records, validate each selected JPEG, and verify its stored digest. A same-path/same-size/same-dimensions replacement must be reported as changed, never silently included. Test that case. Hash the bytes actually streamed into the PDF as well; changed input prevents final publication.
- [ ] After writing/syncing the PDF TMP, append and sync a finish-intent containing final name, size, and PDF SHA-256 before publication. Publish without replacement, then append/sync completed. If reboot finds finish-intent plus an existing final, verify exact digest/size and PDF structure before recording completion. If verification fails, preserve files and show a conflict; never overwrite or blindly resume the finished batch. Add the interruption immediately after final publication/before completed-record test.
- [ ] Acquire storage through the reviewed automatic-mode transition before assembly; writable maintenance must be released. Service UI between chunks; deferred state-changing commands cannot run inside the writer.
- [ ] Inject interruption after every page record, during stream/xref output, and before/after publication. Test mixed 300/600 dpi and page widths, disk-full, missing/changed referenced pages, and maximum bounds. Physically inspect a multipage document and keep JPEG originals after success/failure. Commit `feat: assemble recoverable PDF batches from saved JPEGs`.

## F6 — Receipts and adjustable crop margins

**Files:** extend JPEG proposal logic, settings/menu, corpus in `tests/test_jpeg_pipeline.py`; preserve R5 full validation and original retention.

**Contract:** crop modes remain original-only or derivative-with-original. Add conservative versus receipt proposal settings and a margin in whole MCU units; default retains at least the existing one-MCU margin. A proposed edge is never permission to discard the original.

- [ ] Add synthetic and consented non-private corpus cases for 2-inch receipts, full-width dark photos, sparse text near edges, borders, skew, shadows, and mixed widths. Pin preserved original hashes and derivative content bounds.
- [ ] Replace the unconditional half-canvas rejection only in explicit receipt mode with a verified minimum-width bound and confidence result. Return no proposal for inconsistent edges. Show the selected margin and retain uncertain originals without pretending a crop was correct.
- [ ] Serialize settings through F1's schema and job snapshot. Validate DPI-to-margin conversion; never crop to zero or beyond the encoded frame.
- [ ] Run strict JPEG/content tests and physical receipt/full-sheet comparisons. Commit `feat: add original-preserving receipt crops and margins`.

## F7 — Small previews and document orientation

**Files:** create `jpeg_preview.c/.h`, `tests/test_jpeg_preview.py`; extend menu/rendering, PDF page metadata, capture finalization.

**Contract:** provide a bounded grayscale preview of the last original/derivative, at most 192 x 128 pixels. Generate it while APP owns the file, then retain a RAM thumbnail for viewing during USB ownership. Preview failure never makes a saved scan fail. PDF page rotation supports 0/90/180/270 degrees through page metadata; JPEG originals remain the source of truth.

- [ ] Add asymmetric test images to prove preview orientation, clipping bounds, and grayscale mapping. Validate PDF rotation and page order with the F5 parser/render tests.
- [ ] Use bounded JPEG DC/scaled decoding consistent with R5 validation; avoid a full-resolution frame buffer. Budget preview memory explicitly and fail gracefully when unavailable. Do not open the SD from a UI worker or while USB owns it; requesting a non-cached preview uses an explicit permitted APP transition.
- [ ] Implement preview/rotation controls with F2 gestures. Label low-resolution previews as such. Rotate the display thumbnail and PDF metadata; do not silently re-encode or alter the original JPG.
- [ ] Measure memory/latency at 600 dpi and test allocation failure, return to USB, and viewing while asleep/awake. Confirm physical legibility before enabling by default. Commit `feat: preview saved pages and set PDF orientation`.

## F8 — Signed SD-delivered application updates with rollback

**Depends on:** P2, R3, F2, and a fully accepted current application. **Files:** create `firmware_update.c/.h`, `tests/test_firmware_update.c`, `tools/package_firmware.py`, `docs/qa/update-acceptance.md`; modify component requirements, menu/startup, and signing/rollback config.

**Contract:** the user copies a private signed `UPDATE.BIN` onto SD in writable maintenance mode and safely ejects. The ESP offers an explicit Install action while idle. It validates the image and writes only the inactive application slot. The current bootable application remains available until the candidate passes startup validation. No network service or PC companion is required.

- [ ] Add mocked tests for wrong target/project, malformed/truncated/oversized image, invalid signature, read/write failure, missing inactive partition, unreleased host storage, pending unconfirmed application, and interrupted install. No boot-partition selection may occur before image validation succeeds.
- [ ] Use the IDF 5.5.5 APIs `esp_ota_get_next_update_partition`, `esp_ota_begin`, `esp_ota_write`, `esp_ota_end`, and `esp_ota_set_boot_partition` for the inactive slot. Abort on failure and retain the update file for diagnosis. Validate project/chip/size/version; do not accept arbitrary file bytes as firmware.
- [ ] Create a private signing-key workflow and check in only the public trust material. Use IDF's supported signed-update verification configuration; keep private keys, credentials, and private firmware packages excluded from Git/artifacts. Do not burn security eFuses as part of this software rollout. Document the distinction between update authenticity and physical flash protection.
- [ ] Enable bootloader application rollback. On candidate boot, run bounded internal self-tests and validate the running app with `esp_ota_mark_app_valid_cancel_rollback` only after successful core initialization and a healthy control loop. Scanner/home-network availability is not required for that decision; otherwise an ordinary offline boot would cause a false rollback. Genuine internal failure remains unconfirmed or invokes invalidation/rollback.
- [ ] Install the initial F8-capable bootloader/application configuration through a deliberate BOOT/RESET flash, preserving the verified P2 table and NVS. Verify rollback/signature configuration before accepting the first SD update. The SD updater itself never changes the bootloader; subsequent policy changes that require a new bootloader remain a separate flashing operation.
- [ ] Test interrupted inactive-slot writes, interrupted boot selection, candidate crash, repeated resets before validation, bad signature, and successful update/rollback on the expendable test setup. Confirm existing SD pages, settings schema compatibility, and both slots' hashes. Application updates must never rewrite partition tables or bootloader.
- [ ] Follow the [IDF application update/rollback contract](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32s3/api-reference/system/ota.html); record actual hardware evidence and a recovery flashing procedure. Commit `feat: install signed application updates with rollback`.

- [ ] Ship F1-F3 as a useful controls release before adding batch/document/update complexity.
- [ ] F4-F7 each pass their focused host tests, current reliability suite, resource budget, and documented physical/content checks. Build every release from tracked defaults and pinned dependencies.
- [ ] F8 requires its dedicated destructive/interruption test setup and separate acceptance record; it is never enabled just because its source builds.
- [ ] Update README to describe actual delivered behavior, file naming/original retention/storage cost, maintenance/eject workflow, supported settings, clock state, and feature limits. Keep future proposals labeled until their gates pass.
